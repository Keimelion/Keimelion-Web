# UI kit catalog

The single list of reusable building blocks. **Check it before building any UI**: if a block exists, use it; if it almost fits, extend it here (new prop or variant) rather than writing a look-alike in a feature. See every component in every state, light and dark, with `npm run dev` → `/dev/kit` (tokens: `/dev/tokens`).

## Where things live

| Folder                   | What goes there                                                                                                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/components/ui/`     | Our restyled primitives (shadcn + Radix). **Owned code, edited on purpose.** A primitive added with `npx shadcn add` must be restyled with the tokens before it ships. |
| `src/components/shared/` | Composed, app-wide components. Feature-agnostic: anything domain-specific comes in through props.                                                                      |
| `src/components/icons/`  | Brand line icons (72-unit grid, round caps), occasion shapes, bow geometry. One component per icon. lucide-react only for generic icons the boards do not draw.        |
| `src/lib/motion/`        | Motion presets, `MotionEasings`, `MotionDurations`, `useShouldReduceMotion()`.                                                                                         |
| `src/lib/occasions/`     | `getOccasionPaper()`, occasion shapes, paper class names.                                                                                                              |

`src/components/` never imports from `src/features/` or `src/data-access/` (enforced by ESLint).

## Contracts every component follows

- **Form controls** forward `ref`, `id`, `aria-describedby`, `aria-invalid` and `disabled`, so they drop into `<FormControl>`; help text and error are both announced.
- **Touch targets** are ≥ 44 × 44 px below `lg`: add the `touch-target` class to anything visually smaller. Inline controls carry `w-fit` so a flex or grid parent never stretches them.
- **Colours** come from tokens only (hex is a lint error). Selection is `brand`/`on-brand`; toasts are `inverse`.
- **Motion** plays once on its trigger, never loops (one deliberate exception: the 404 parcel floats with `bob` on repeat), and jumps to the end state under reduced motion.
- **Copy**: components only carry generic labels (Cancel, Close, Show password…) from `common.*`; every other string is a prop.

## Adding a component

1. Check this catalog and `/dev/kit` first; extend before duplicating.
2. Put it in `ui/` (primitive) or `shared/` (composed), one component per file, folder when it has a test.
3. Follow the contracts above (form control, touch target, tokens, motion, copy).
4. Add it to `/dev/kit` (`src/features/ui-kit/`) in every state, with tests, and to this catalog in the same PR.
